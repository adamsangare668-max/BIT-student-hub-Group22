📘 Résumé du cours

🔹 Contexte : projet Burkina Rescue

Gestion d'une file d'attente de victimes en salle de triage (SAMU). Les victimes sont prises en charge dans l'ordre d'arrivée : Ali → Paul → Jean → Awa.

🔹 Principe FIFO

FIFO (First In, First Out) : « Premier arrivé, premier servi ».

  • L'élément inséré en premier est le premier retiré.
  • Les insertions se font à l'arrière (rear).
  • Les suppressions se font à l'avant (front).
Exemple concret : une file d'attente à un guichet.

🔹 Comparaison Pile (LIFO) vs File (FIFO)

CaractéristiquePile (Stack)File (Queue)
PrincipeLIFOFIFO
InsertionSommetArrière (rear)
SuppressionSommetAvant (front)
Exemple réelPile d'assiettesFile d'attente

Dans le projet SAMU : la pile sert pour l'historique des interventions, la file pour la salle d'attente.

🔹 Représentation et pointeurs

Une file possède deux extrémités :

  • front : pointe vers le premier élément (celui à retirer).
  • rear : pointe vers le dernier élément (dernier arrivé).

front → Ali → Paul → Jean ← rear

Contraste avec la pile : la file nécessite deux pointeurs, la pile un seul (top).

🔹 Structures en C

Nœud (victime) :

typedef struct Node {
    int id;
    char victime[50];
    int priorite;
    struct Node *suivant;
} Node;

File :

typedef struct File {
    Node *front;
    Node *rear;
} File;

Initialisation :

File f;
f.front = NULL;
f.rear = NULL;

📝 Exercices corrigés

Exercice 1 – Initialisation et structure

Énoncé :

  1. Pourquoi initialise-t-on front et rear à NULL ?
  2. Que signifie front == NULL ?

Correction

1. Initialiser front et rear à NULL représente une file vide. C'est un état de base cohérent : aucun élément n'est présent. Cela permet aux fonctions comme enqueue() de détecter facilement ce cas et de positionner correctement les deux pointeurs sur le premier nœud ajouté.

2. front == NULL est la condition de file vide. Comme front pointe toujours vers le premier élément, s'il est NULL, il n'y a aucun élément. Cette vérification est essentielle avant d'appeler dequeue() ou front() pour éviter les erreurs de segmentation.

✔ Réponse : initialisation à NULL = file vide ; front == NULL signifie que la file est vide.
Exercice 2 – Complexité et cas d'erreur

Énoncé :

  1. Pourquoi enqueue() est-elle en O(1) ?
  2. Pourquoi dequeue() est-elle en O(1) ?
  3. Que se passe-t-il si on appelle dequeue() sur une file vide ?

Correction

1. L'ajout se fait à l'arrière. Grâce au pointeur rear, on a un accès direct à la fin de la file. Les opérations (allocation, liaison, mise à jour de rear) sont en nombre constant, indépendant de la taille n de la file → O(1).

2. La suppression se fait à l'avant. Le pointeur front donne un accès direct au premier élément. Déplacer front vers front->suivant est une opération constante → O(1).

3. Appeler dequeue() sur une file vide (i.e., front == NULL) provoque une erreur de segmentation car on tente d'accéder à front->suivant alors que front ne pointe sur rien. Une implémentation robuste doit toujours vérifier if (f.front == NULL) return; ou afficher un message d'erreur.

✔ enqueue O(1), dequeue O(1) ; sur file vide → erreur (à prévenir par une vérification).
Exercice 3 – Conception et applications

Énoncé :

  1. Pourquoi la file nécessite-t-elle deux pointeurs contrairement à la pile ?
  2. Donner trois exemples d'utilisation d'une file en informatique.

Correction

1. La pile est LIFO : toutes les opérations se font à la même extrémité (le sommet), un seul pointeur suffit. La file est FIFO : les insertions et les suppressions se font à deux extrémités distinctes (arrière et avant). Pour garantir que ces deux opérations soient en O(1), il faut maintenir deux pointeurs (front et rear). Sans rear, l'ajout nécessiterait un parcours en O(n).

2. Trois exemples :

  • Ordonnancement des tâches (scheduling) : les processus en attente d'exécution sont dans une file (file d'attente prête). Le planificateur prend le premier.
  • Gestion des impressions (spooling) : les documents à imprimer sont mis en file d'attente, traités dans l'ordre d'arrivée.
  • Files d'attente dans les serveurs web : les requêtes HTTP sont placées dans une file pour être traitées par les workers disponibles.
✔ File = 2 pointeurs pour FIFO efficace ; exemples : ordonnancement, impression, requêtes web.
Exercice 4 – Fonction front()

Énoncé : Pourquoi la fonction front() ne modifie-t-elle pas la file ? Quelle est sa complexité algorithmique ?

Correction

Pourquoi front() ne modifie pas la file ?

La fonction front() a pour seul but de consulter l'élément en tête sans le retirer. Elle se contente de lire les données du nœud pointé par f.front. Elle ne modifie ni les pointeurs (front, rear), ni le contenu des nœuds. C'est une fonction d'observation (getter).

Complexité : O(1). L'accès à la tête est direct via le pointeur front, sans parcours, donc temps constant.

✔ front() est en lecture seule, O(1) – ne modifie pas la file.
