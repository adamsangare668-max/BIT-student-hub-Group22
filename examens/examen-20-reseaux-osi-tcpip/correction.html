📋 Énoncé résumé

L'examen sur les réseaux porte sur les modèles OSI et TCP/IP :

  1. décrire les 7 couches du modèle OSI ;
  2. comparer avec le modèle TCP/IP à 4 couches ;
  3. analyser une trame Ethernet et un paquet IP ;
  4. expliquer le fonctionnement du three-way handshake TCP.
Définition — Modèle OSI. Le modèle OSI (Open Systems Interconnection), normalisé par l'ISO en 1984, est un modèle de référence en 7 couches qui décrit les fonctions d'un système de communication réseau. Chaque couche offre des services à la couche supérieure et utilise ceux de la couche inférieure. C'est un cadre théorique qui sert de base à l'enseignement et à la standardisation des protocoles.

💡 Méthodologie

  1. Mémoriser les 7 couches OSI (mnémonique : « Pour Le Réseau Tout N'est Pas Si Simple »).
  2. Associer à chaque couche des protocoles et équipements.
  3. Comprendre l'encapsulation : chaque couque ajoute son en-tête.
  4. Comparer avec TCP/IP (4 couches) : Application, Transport, Internet, Accès réseau.

TCP/IP est plus pragmatique : les couches 5, 6, 7 d'OSI sont fusionnées dans la couche Application, et les couches 1, 2 dans Accès réseau. TCP/IP est implémenté (Internet réel) tandis qu'OSI est théorique.

Question 3 — Encapsulation d'une requête HTTP

Soit une requête HTTP GET vers http://exemple.com/index.html :

  1. Application : « GET /index.html HTTP/1.1\r\nHost: exemple.com\r\n\r\n »
  2. Transport : ajout en-tête TCP (port source 54321, port dest 80, seq, ack, flags SYN/ACK/PSH).
  3. Réseau : ajout en-tête IP (IP source 192.168.1.10, IP dest 93.184.216.34, TTL 64).
  4. Liaison : ajout en-tête Ethernet (MAC source AA:BB:CC:DD:EE:FF, MAC dest MAC du routeur, type 0x0800).
  5. Physique : conversion en signaux électriques (câble cuivre) ou lumineux (fibre).

À la réception, chaque couche décapsule : Ethernet lit son en-tête et transmet le paquet IP à la couche 3, qui transmet le segment TCP à la couche 4, qui reconstitue le flux de données et le transmet au serveur HTTP.

Question 4 — Three-way handshake TCP

Client                          Serveur
  |--- SYN (seq=x) ------------>|
  |<-- SYN-ACK (seq=y, ack=x+1)-|
  |--- ACK (ack=y+1) ----------->|
  |                             |
  |=== connexion établie ========|

Le client envoie un segment SYN avec un numéro de séquence initial x. Le serveur répond par SYN-ACK avec son propre numéro y et acquitte x+1. Le client confirme par ACK y+1. La connexion est alors établie dans les deux sens (full-duplex). Chaque octet envoyé est numéroté et acquitté, ce qui permet la retransmission en cas de perte.

Exemple appliqué. Lorsqu'on tape une URL dans le navigateur, le modèle TCP/IP se traduit par : DNS (couche Application) résout le nom en IP, TCP (couche Transport) ouvre la connexion vers le port 443, IP (couche Internet) route les paquets à travers plusieurs routeurs, Ethernet/Wi-Fi (couche Accès) transmet sur le lien local. Au final, une page web implique des dizaines d'allers-retours à travers ces 4 couches.

📝 Notes importantes

  • Encapsulation : chaque couche ajoute son en-tête, ce qui induit une overhead (ex : en-têtes TCP/IP = 40 octets par segment). Important pour les protocoles temps réel.
  • Connexion vs sans connexion : TCP est orienté connexion (fiable), UDP est sans connexion (rapide, mais sans garantie).
  • Adressage : IP = adresse logique (routeur), MAC = adresse physique (switch). ARP fait le lien.
  • MTU : Maximum Transmission Unit, taille max d'une trame (1500 octets en Ethernet standard). La fragmentation IP intervient au-delà.

📚 Pour aller plus loin

  • Les VPN (IPsec, OpenVPN, WireGuard) chiffrent les données au niveau de la couche 3 (IPsec) ou 6 (TLS-based VPN).
  • Les SDN (Software Defined Networks) séparent le plan de contrôle du plan de données pour virtualiser le réseau.
  • QUIC (HTTP/3) remplace TCP+TLS par un protocole UDP chiffré et multiplexé, réduisant la latence.
  • IPv6 (128 bits) répond à la pénurie d'IPv4 (32 bits) : 340 sextillions d'adresses contre 4,3 milliards.
  • Les outils tcpdump, Wireshark, nmap permettent d'analyser le trafic réel selon les couches OSI.
