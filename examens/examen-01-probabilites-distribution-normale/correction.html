Distribution Normale — Exercice 3

Correction pédagogique.

Cette correction a été rédigée par l'équipe BIT Study HUB pour vous aider à comprendre la démarche attendue. Le sujet original (image) peut comporter des variantes : adaptez les calculs à vos valeurs numériques précises.

📋 Énoncé résumé

La demande journalière X d'une plateforme numérique suit une loi normale d'espérance μ = 500 connexions et d'écart-type σ = 50 connexions. Le sujet demande de calculer la probabilité que la demande dépasse 600 connexions, celle qu'elle soit inférieure à 450, puis la probabilité qu'elle soit comprise entre 450 et 600. Une dernière question porte sur la valeur x telle que P(X ≤ x) = 0,95.

Définition — Loi normale centrée réduite. Si X ~ 𝒩(μ, σ2), la variable Z = (X − μ) / σ suit la loi normale 𝒩(0, 1). Sa fonction de répartition se note Φ(z) = P(Z ≤ z) et se lit dans la table de la loi normale.

💡 Méthodologie

  1. Identifier les paramètres μ et σ de la variable X.
  2. Centrer et réduire en posant Z = (X − μ)/σ.
  3. Calculer la valeur seuil z correspondant à la borne x demandée.
  4. Lire la probabilité Φ(z) dans la table.
  5. Adapter selon le sens de l'inégalité : P(X > x) = 1 − Φ(z), P(X < x) = Φ(z).

✅ Solution détaillée

Question 1 — P(X > 600)

On calcule z = (600 − 500)/50 = 100/50 = 2. La table donne Φ(2) ≈ 0,9772, donc :

P(X > 600) = 1 − Φ(2) = 1 − 0,9772 = 0,0228

Soit environ 2,28 % de chances que la demande journalière dépasse 600 connexions.

Question 2 — P(X < 450)

z = (450 − 500)/50 = −1. Par symétrie de la loi normale, Φ(−1) = 1 − Φ(1) = 1 − 0,8413 = 0,1587.

P(X < 450) = Φ(−1) ≈ 0,1587

Soit environ 15,87 %.

Question 3 — P(450 ≤ X ≤ 600)

On soustrait les deux résultats :

P(450 ≤ X ≤ 600) = Φ(2) − Φ(−1)
                       = 0,9772 − 0,1587 = 0,8185

Soit 81,85 % : c'est la probabilité que la demande reste dans une plage « normale » d'exploitation.

Question 4 — Quantile à 95 %

On cherche x tel que P(X ≤ x) = 0,95. On lit dans la table z0,95 ≈ 1,645, d'où :

x = μ + z · σ = 500 + 1,645 × 50 ≈ 582,25

La plateforme peut prévoir une capacité d'environ 583 connexions pour couvrir 95 % des jours.

Exemple appliqué. Si l'infrastructure est dimensionnée à 582 connexions simultanées, seuls 5 % des jours dépasseront ce seuil. C'est le raisonnement utilisé par les ingénieurs DevOps pour le « capacity planning ».
Exercice d'application. Reprenez la méthodologie ci-dessus avec des valeurs numériques différentes (par exemple un autre jeu de paramètres) et vérifiez que vous arrivez au bon résultat. Puis essayez de refaire l'exercice sans regarder la solution : c'est la meilleure façon de fixer durablement la méthode.

📝 Notes importantes

  • Erreur fréquente : oublier de réduire X en Z avant de lire la table. Toujours passer par Z = (X − μ)/σ.
  • Symétrie : Φ(−z) = 1 − Φ(z). Utile quand la table ne donne que les valeurs positives.
  • Unités : μ et σ doivent avoir la même unité que X.
  • Approximation : pour σ petit, la distribution est très concentrée autour de μ (loi « piquée »).

📚 Pour aller plus loin

  • Le théorème central limite justifie l'omniprésence de la loi normale : une somme de variables indépendantes tend vers une loi normale, ce qui explique pourquoi la demande agrégée d'une plateforme est bien modélisée par 𝒩(μ, σ2).
  • La règle 68-95-99,7 : ~68 % des valeurs sont dans [μ−σ ; μ+σ], ~95 % dans [±2σ], ~99,7 % dans [±3σ].
  • Lien avec la loi binomiale : pour n grand, B(n, p) est approchée par 𝒩(np, √(np(1−p))).
  • Outil pratique : en Python, scipy.stats.norm.cdf(z) donne Φ(z) sans recourir à la table.
