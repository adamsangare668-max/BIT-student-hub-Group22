📋 Énoncé résumé

L'examen porte sur le routage et les protocoles associés :

  1. différencier routage statique et dynamique ;
  2. comparer RIP (distance vector) et OSPF (link state) ;
  3. construire la table de routage d'un routeur à partir d'une topologie ;
  4. expliquer le rôle de BGP pour le routage inter-AS.
Définition — Routage. Le routage est le processus qui consiste à déterminer le prochain saut (next hop) vers la destination d'un paquet IP. Chaque routeur maintient une table de routage qui associe des préfixes réseau (ex : 192.168.0.0/24) à une interface de sortie et/ou un routeur voisin. Les protocoles de routage (RIP, OSPF, BGP) permettent de peupler automatiquement cette table en échangeant des informations entre routeurs.

💡 Méthodologie

  1. Identifier le type de routage (interne/externe, statique/dynamique).
  2. Comprendre les algorithmes : distance vector (Bellman-Ford) vs link state (Dijkstra).
  3. Calculer les métriques (sauts RIP, coût OSPF = 108/bande passante).
  4. Construire la table en suivant le plus court chemin.

Question 3 — Table de routage d'un routeur R1

Topologie :

  [LAN1: 10.0.1.0/24]
        |
       R1 ---- R2 ---- [LAN2: 10.0.2.0/24]
        |        |
       R3 ---- R4
        |
   [LAN3: 10.0.3.0/24]

Métrique : 1 par lien. Table de routage de R1 :

Si le lien R1-R3 tombe, R1 atteint LAN3 via R2 → R4 → R3 (métrique 3). OSPF converge en quelques secondes après échange de LSA.

Question 4 — BGP (Border Gateway Protocol)

BGP est le protocole de routage inter-AS (Autonomous Systems) qui assure le routage sur Internet. Chaque AS (FAI, grande entreprise) est identifié par un numéro (ASN, 32 bits). BGP échange des préfixes IP avec les AS voisins via TCP (port 179).

Caractéristiques :

  • Path vector : la métrique est un chemin d'AS (ex : AS100 → AS200 → AS300).
  • Politiques de routage : chaque AS peut filtrer ou modifier les routes (BGP attributes : LOCAL_PREF, MED, AS_PATH).
  • Évite les boucles : un AS refuse une route qui le contient déjà dans AS_PATH.
  • eBGP entre AS différents, iBGP à l'intérieur d'un AS.

BGP est path vector et non link-state : il optimise la politique plutôt que la métrique technique. C'est ce qui permet à Internet de fonctionner malgré la diversité des opérateurs.

Exemple appliqué. Quand vous chargez un site web, vos paquets traversent plusieurs AS : votre FAI local (AS X) → un opérateur de transit (AS Y) → le FAI de l'hébergeur (AS Z). La commande traceroute révèle ces sauts. Une table BGP complète d'Internet contient aujourd'hui plus de 900 000 préfixes IPv4.
Exercice d'application. Reprenez la méthodologie ci-dessus avec des valeurs numériques différentes (par exemple un autre jeu de paramètres) et vérifiez que vous arrivez au bon résultat. Puis essayez de refaire l'exercice sans regarder la solution : c'est la meilleure façon de fixer durablement la méthode.

📝 Notes importantes

  • Convergence : temps nécessaire à tous les routeurs pour mettre à jour leurs tables après un changement topologique.
  • Count to infinity : problème classique de RIP, atténué par split horizon et route poisoning.
  • Areas OSPF : la zone 0 (backbone) doit connecter toutes les autres areas, ce qui structure la hiérarchie.
  • Sécurité : les protocoles de routage doivent être authentifiés (MD5, IPsec) pour éviter l'empoisonnement de table.

📚 Pour aller plus loin

  • EIGRP (Cisco) : hybride avancé, efficace mais propriétaire.
  • IS-IS : protocole link state utilisé par les très grands opérateurs (alternative à OSPF).
  • SD-WAN : virtualise le routage WAN en séparant plan de données et plan de contrôle.
  • Segment Routing (SR-MPLS) : simplifie le traffic engineering en encodant le chemin dans le paquet.
  • Outils : show ip route (Cisco IOS), ip route (Linux), bird, FRRouting.
